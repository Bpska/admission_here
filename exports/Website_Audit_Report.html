01 / Security priorities

CRITICAL · source-confirmed · S1

Remove the administrator password fallback

Observed: The credentials provider accepts two hardcoded alternative passwords for a specific administrator account after the stored password hash fails.

Why it matters: The fallback defeats the normal password verification for that account if those values become known. Exploitability was not tested.

Recommended action: Remove the fallback, rotate administrator credentials and review existing sessions. Verify that only the current hashed password authenticates.

Evidence: src/lib/auth/config.ts · authorize()

HIGH · source-confirmed · S2

Require explicit production secrets

Observed: Authentication and Docker Compose contain fallback authentication secrets; Compose also supplies a default database password.

Why it matters: A deployment that omits its environment settings may use predictable secrets or credentials. The live configuration is unknown.

Recommended action: Fail startup when production secrets are missing. Use unique environment-managed values and rotate any default already used.

Evidence: src/lib/auth/config.ts; docker-compose.yml

HIGH · deployment-dependent · S3

Restrict database port exposure

Observed: Compose publishes the PostgreSQL service port on the host without an explicit loopback bind.

Why it matters: Depending on host firewall and network rules, the database may be reachable outside the application network.

Recommended action: Remove the published database port for deployment, or bind it to loopback and enforce firewall rules.

Evidence: docker-compose.yml · postgres.ports

05 / SEO, accessibility and performance

MEDIUM · source-confirmed · Q1

Confirm the real brand and canonical domain

Observed: Metadata helpers and robots fall back to an AdmissionsHub domain/brand when the public URL is absent.

Why it matters: Wrong configuration can produce canonical and sitemap references to a different domain and inconsistent page branding.

Recommended action: Set NEXT_PUBLIC_APP_URL to the real HTTPS domain. Review shared metadata branding, canonical URLs, robots and sitemap on staging.

Evidence: src/lib/seo/metadata.ts; src/app/robots.ts

SEO capabilities present

Metadata helpers, sitemap and robots routes, structured data, breadcrumbs and programme-specific URLs are implemented. Their presence is not proof of valid search indexing. Inspect rendered metadata, duplicate/filter URLs, indexability and Search Console after deployment.

Accessibility

The public probe checks for missing image alt attributes, but an existing alt attribute can still be empty or poor. A full keyboard, screen-reader, contrast and focus-order audit was not performed. Test all dialogs and rich-text controls with keyboard navigation and verify informative images have useful text alternatives.

Performance

No Lighthouse score or Core Web Vitals result is claimed. Measure LCP, INP and CLS on the deployed site with representative devices and content. Review image dimensions, database query costs, cache behavior and directory pagination under load.

Operations

Verify HTTPS, secure cookies, reverse-proxy headers, request logging, error alerts and backup monitoring in the deployment environment. These cannot be established from a local layout check.
